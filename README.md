# AI美食聊天機器人
## 開發與審核守則 (SOP)
- 為確保系統穩定與實作進度透明，本專案實施以下開發規範：

1. 禁止直接 PUSH 至 main 分支。所有開發請在個人分支 (feature/成員名-部件名) 進行。
2. 功能完成後，須發起 Pull Request (PR) 申請合併。
3. PR 必備訊息（未達標直接退件）：
   - 對應章節：明確標註此代碼對應文件中的哪一個實作章節（例：對應 3.2 節）。
   - 實作成果：簡述本次修改的功能邏輯（做了什麼？）。
   - 運行證明：必須附上測試截圖或 Log 紀錄，證明代碼可在本地跑通。
   - 待辦事項：若功能未全完，請標註剩餘進度。
4. 所有代碼須經由會議中經指導教授審核通過方可併入主系統。
5. GitHub Commit 紀錄將作為「對著文件說話」的唯一實作證據。
## **專案介紹**

- 本專題旨在打造一個專為本校學生設計的台南美食聊天助理,協助同學以最自然,最直覺的方式快速探索校園周邊餐廳。為達成此目標,本專題規劃以下功能與技術實作面向:
1. 建置專屬於本校學生的台南美食資料庫以Google Maps為主要資料來源，整理校園一公里內的餐廳資訊。
- 使用 MySQL 建立餐聽硬資訊的資料庫。
   - 店名
   - 地址
   - 評分
   - 連絡電話
   - 營業時間
   - 經緯度
   - 原始評論
- 使用 Qdrant 建立餐聽軟資訊的資料庫。
   - 店家id(查詢MySQL使用)
   - 菜系
   - 食物種類
   - 口味
   - 氣氛
   - 評論摘要
2. 以單一 LLaMA 模型作為核心語意理解引擎本專題不使用傳統 NLP 模組分工，而是透過 一個微調後的 LLaMA 模型，在開發的模型任務流程中完成：
- 中文自然語言理解
- 使用者意圖辨識
- 槽位抽取（如食物類型、預算、距離、限制條件等)
- 對話上下文理解
- 多輪對話管理
- 使整體系統架構更簡潔，也讓回應更加一致、自然。
4. 建立自然對話式的美食推薦流程讓使用者能以一般口語方式詢問，如
-「想吃便宜的」
-「幫我找學校附近 10 分鐘內的咖哩」
-「第二家可以預約嗎？」
- 模型會主動釐清資訊不足之處並提出補問。
- 回應內容會依照對話歷史進行智能調整，完整呈現多輪對話能力。
5. 完成資料查詢、推薦與格式化輸出後端 API 根據 LLaMA 抽出的槽位查詢資料庫。將查詢結果整理成 卡片式回覆格式，如：
- 店名
- 評分
- 地址與距離
- 菜系
- 食物種類
- 店家類型
- 營業時間
- 店家評論
- 讓前端 App 可直覺呈現美食資訊。
6. 完成系統部署並提供可展示的完整 Demo
- 使用Docker Compose部屬 Main API、MySQL、Qdrant、Search API、LLM API。
- 讓前端 App 能穩定連線、發出查詢、接收推薦並展示結果。
- 展示從「語意理解 → 查詢 → 回覆生成」的完整 AI 美食推薦流程。
